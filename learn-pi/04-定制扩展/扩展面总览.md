# 扩展面总览

二次开发 Pi，先选对「钉子」。

## 能力光谱（从浅到深）

```
Themes
  └─ 只改观感

Prompt Templates
  └─ slash 展开固定提示

Skills
  └─ 教模型何时/如何用某套流程或 CLI

Extensions (TypeScript)
  └─ 新工具、钩子、命令、UI、自定义 Provider、改系统提示…

Pi Packages
  └─ 把上面资源打包成可 npm/git 安装的单元

SDK / RPC / JSON
  └─ 换宿主：你的应用 / IDE / 编排器

Containerization / 权限扩展
  └─ 换信任边界：微 VM、Docker、确认门
```

## 决策树

```
只想改颜色/样式？ → Theme
只想要一条可复用提示？ → Prompt Template
想给模型「按需说明书」？ → Skill
要拦工具 / 加工具 / 加命令 / 改 UI / 自定义登录？ → Extension
要分发给别人或多个项目复用？ → 打成 Pi Package
要嵌进自己的后端/IDE？ → SDK 或 RPC
要隔离文件系统/网络？ → Containerization 或 permission extension
要改 tool-call 循环语义本身？ → 才考虑动 pi-agent-core
```

## 为什么这种光谱适合初学者

- 每一档都有**独立文档**和**可运行例子**
- 失败成本低：弄坏一个 skill 不会搞崩循环
- 进阶路径清晰：Skill → 小 Extension → Package → SDK

## 为什么这种光谱适合二次开发

- **不必 fork** 就能做出 Plan Mode / 子 Agent / 权限门（仓库 examples 已证明）
- **分发路径**内置（`pi install` / packages）
- **嵌入路径**内置（SDK/RPC），产品与库同构

## 安全提醒（所有扩展面共用）

扩展与主进程同权。装第三方 package ≈ 跑别人的代码。  
生产环境用容器或自己的 permission 策略；不要假设「扩展 API」等于沙箱。
