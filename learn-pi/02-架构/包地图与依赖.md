# 包地图与依赖

## Monorepo 一览

根目录 `package.json` 的 `workspaces` 包含 `packages/*` 与部分 example 扩展包。

| 目录 | npm 名 | 一句话 |
|------|--------|--------|
| `packages/ai` | `@earendil-works/pi-ai` | 统一多厂商 LLM（stream、tools、模型目录） |
| `packages/agent` | `@earendil-works/pi-agent-core` | Agent 运行时：循环、工具、事件、Harness |
| `packages/tui` | `@earendil-works/pi-tui` | 终端 UI（差分渲染，不依赖 AI） |
| `packages/coding-agent` | `@earendil-works/pi-coding-agent` | 编码 Agent CLI / SDK / 扩展生态 |
| `packages/storage/sqlite-node` | `@earendil-works/pi-storage-sqlite-node` | 可选 SQLite 会话后端 |
| `packages/server` | `@earendil-works/pi-server` | 实验性服务端封装 |
| `packages/evals` | （内部评测） | 行为评测 |

## 依赖方向（必须记住）

```
                    ┌─────────┐
                    │  pi-tui │  （叶子，独立）
                    └────▲────┘
                         │
┌─────────┐        ┌─────┴──────────┐        ┌──────────┐
│  pi-ai  │───────►│ pi-agent-core  │◄───────│ sqlite-  │
└────▲────┘        └────────▲───────┘        │  node    │
     │                      │                └──────────┘
     │                      │
     └──────────┬───────────┘
                │
         ┌──────┴──────────┐
         │  coding-agent   │
         └────────▲────────┘
                  │
         ┌────────┴────────┐
         │     server      │
         └─────────────────┘
```

**构建顺序**（根脚本）：

`tui → ai → agent → storage/sqlite-node → coding-agent → server`

为什么这样排：

1. `tui` 无上游包依赖，先编
2. `ai` 是 agent 的底座
3. `agent` 再被 coding-agent / sqlite 使用
4. 产品包最后，server 挂在最外

## 每层该解决什么问题

### pi-ai

- Provider 差异屏蔽（OpenAI / Anthropic / Google / …）
- 流式响应与 tool call 结构统一
- 模型目录（生成数据在 `src/providers/data/`，**gitignore**，需 hydrate / generate）

**学习者**：先会 `createModels` + `streamSimple`，不必先懂全部 provider。

### pi-agent-core

- `Agent` / `agentLoop`：多轮工具循环
- 事件：`agent_start` / `turn_*` / `message_*` / `tool_execution_*`
- `AgentMessage` vs LLM `Message`（`convertToLlm`）
- Harness / Session 持久化设计

### pi-tui

- 组件、`requestRender`、差分更新、overlay
- coding-agent 的交互模式建立在这之上
- 也可被 extension 用来做自定义 UI

### pi-coding-agent

- CLI 入口、设置、鉴权、资源发现（extensions/skills/…）
- `AgentSession`：产品级会话门面
- 四种模式 + SDK

### sqlite-node

- 刻意拆包：避免 agent-core 默认拖入原生 SQLite / Node builtin 假设

## 版本策略

各包通常 **lockstep** 同版本号（见 `AGENTS.md` 发布规则）。学版本时看任意 `packages/*/package.json` 的 version 即可对齐。

## 和「为什么适合二次开发」的关系

分层让二次开发有三种深度：

| 深度 | 改哪里 | 典型场景 |
|------|--------|----------|
| 浅 | 只加 coding-agent 资源（skill/extension/package） | 工作流定制 |
| 中 | 依赖 `pi-ai` / `pi-agent-core` 写自己的宿主 | 嵌入应用 |
| 深 | fork 改某层并保持接口 | 协议/循环语义创新 |

大多数人应停在「浅」；Pi 的设计就是让「浅」足够强。
