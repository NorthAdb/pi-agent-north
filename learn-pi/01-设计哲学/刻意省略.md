# 刻意省略（Intentional Omissions）

官方 Philosophy 明确列出一组 **No**：这些不是 roadmap 上的「还没写」，而是**刻意不放进内核**。理解这一点，才能理解为什么 Pi「看起来功能少，却适合二次开发」。

以下除特别标注外，摘自 / 转述自 `packages/coding-agent/README.md` Philosophy。

> **版本注记（1.0.2 复核）**：本清单是 Philosophy 的「不进内核」列表。0.99.0 把 MCP 做成了内置扩展，1.0 没有把它收回 Core。
> 「不进内核」仍然成立，「Pi 没有 MCP」这句老话不准确。见下节。

## MCP：从「刻意省略」到「内置扩展」

- **Core 的立场没变**：Core 工具仍是 `read` / `write` / `edit` / `bash`；MCP 不是第五个内置工具。
- **实现位置变了**：0.99.0 起 MCP 随 Pi 以**内置扩展**加载（`packages/coding-agent/src/extensions/index.ts:7-14`，
  客户端库在 `packages/mcp`）。它标记为 `replaceable: true`——第三方扩展可以整个顶掉它。
- **默认不占上下文**：服务器默认 `exposure: "codemode"`（`src/extensions/mcp/index.ts` 文件头）。
  MCP 工具不声明给模型，也不进 codemode 的工具清单。脚本用 `searchTools()` / `describeNamespace()` 按需发现。
  非 `direct` 的服务器在后台连接，不挡住第一条 prompt。
- **配置与命令**：用户级 `~/.pi/agent/mcp.json`，加上受信任项目的 `.pi/mcp.json`。项目文件可以只写 `enabled` / `exposure` / `toolExposure`，覆盖同名的用户级服务器，不必重写启动命令。命令是 `pi mcp add|remove|list|login|logout`，会话内是 `/mcp`。
  见 `packages/coding-agent/docs/mcp.md`。
- **二次开发**：先用 `pi mcp add`（零代码）；要按环境动态注册，用 `pi.registerMcpServer()` / `pi.getMcpServers()` /
  `mcp_servers_change` 事件。
- **延伸**：[What if you don't need MCP?](https://mariozechner.at/posts/2025-11-02-what-if-you-dont-need-mcp/)（理解上下文预算的必读）、`packages/coding-agent/docs/mcp.md`

## No sub-agents（无内置子 Agent）

- **立场**：子 Agent 有很多做法——tmux 再开一个 `pi`、自己写 extension、或装别人的 package。
- **仓库里已有参照**：`packages/coding-agent/examples/extensions/subagent/`
- **启示**：编排策略属于工作流，不属于「所有人必须同一套」的内核。

## No permission popups（无权限弹窗）

- **立场**：在容器里跑，或用 extension 做确认流，贴合你的环境与合规。
- **根 README**：Pi **没有**内置限制文件系统/进程/网络/凭据的权限系统；默认 = 启动用户权限。
- **隔离方案文档**：`packages/coding-agent/docs/containerization.md`（Gondolin / Docker / OpenShell）
- **例子**：`examples/extensions/` 下的 permission / confirm 类扩展（如 `permission-gate`、`confirm-destructive`）

## No plan mode

- **立场**：计划写成文件，或用 extension / package。
- **参照**：`examples/extensions/plan-mode/`

## No built-in to-dos

- **理由（官方）**：内置 TODO **会迷惑模型**。
- **替代**：`TODO.md`，或自己做 extension（例子里有 todo 相关工具）。

## No background bash

- **立场**：用 **tmux**。可观察、可直接交互。
- **文档**：`packages/coding-agent/docs/tmux.md`

## 省略表的统一逻辑

```
若功能满足：
  ① 有多种合理实现；且
  ② 强绑内核会限制工作流或迷惑模型；且
  ③ 能用扩展/包/外部工具表达
→ 就不进内核。
```

> MCP 是这套逻辑的新样本：它没有进 Core，而是进了**可替换的内置扩展**——介于「核心」与「用户扩展」之间的第三种归属。

这就是「适合二次开发」的根源：**空白处是扩展市场，不是产品缺陷。**

## 学习者怎么对待省略

1. **先接受默认**：四个工具 + 会话，完成真实改代码任务  
2. **缺什么再补什么**：需要确认再装/写 permission；需要并行调研再看 subagent 例子  
3. **不要一上来把所有 No 都用扩展填满**——那会把自己做成另一个巨型产品，丢掉 Pi 的清晰度  

## 对照：内核「有」的东西

省略之外，内核**坚持提供**的，往往是跨工作流都稳定的基础设施：

- 多模型 / 多厂商
- Agent 循环与工具执行语义
- 会话格式与分支 / compaction
- 扩展加载与 API 面（含一组可替换的**内置扩展**：`llama.cpp`、`codemode`、`tool-search`、`mcp`）
- TUI / RPC / SDK 出口

学 Pi = 分清 **基础设施** vs **工作流插件**。
